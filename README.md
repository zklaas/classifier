# Classifier

**A Linux tool for developers.** Classifier runs on Linux only. The software it looks
after can be for any operating system: it records Windows, macOS and other platform
support, and writes installers' instructions for them. Classifier itself stays on Linux,
because its licence texts come from Linux's `/usr/share/common-licenses` and *Review
with Claude* runs Claude in a Linux Docker container.

## Download

Ready-to-run downloads (executable programs), with nothing else to install:

* **Linux:** [Classifier-Linux-x86_64.AppImage](https://github.com/zklaas/classifier/releases/latest/download/Classifier-Linux-x86_64.AppImage)

The [release page](https://github.com/zklaas/classifier/releases/latest) says how to run it.
To install from the source code at the command line instead, see below.

Sorts your software into **Development Groups**, decides which of it is **Cleared**
for an open-source licence, writes that licence (with an AI disclosure naming Claude),
records which operating systems each one supports, and keeps GitHub in line.

Run `classifier` for the window, or `classifier --help` for the terminal commands.
Install with `./install.sh` (launcher, desktop entry and icon, and
`claude-classifier-docker`). Needs a Linux desktop with Python 3 and PyQt6, the `gh`
CLI and `git` for the GitHub features, and Docker for *Review with Claude*.

## Development Groups

| | Cleared | Not Cleared |
|---|---|---|
| Finished, on its own | Releasable By Itself | Finished but Private |
| Module of a suite | Releasable but Unfinished As Modular Suite | Modular Suite but Private |
| In development, on its own | In Development and Private | In Development and Private |

A group can be chosen by hand, but software that is not Cleared can never be put in a
Releasable group. Software whose stage is not set is *Not yet classified*, and
Classifier takes no GitHub action on it.

## Cleared

Scanned, unchanged since the scan, every provenance item resolved acceptably, and the
licensor's confirmation ticked. The scan (`classifier/scanner.py`; the **How the scan
works…** button explains it) finds copyright notices and licence wording, vendored or
minified code, Python and JavaScript dependencies (imports, `require`, `package.json`,
CDN links), assets (images, sound, fonts, data …) and git authors. Each item is
resolved as the licensor's own work, Claude's, generated by the software's code,
following the language's logic, open-source (with a named open licence), or excluded
from release. Unknown or non-open origin blocks clearance.

**Review with Claude…** opens Claude in `claude-classifier-docker` on the folder
(read-only; it writes only `.classifier-review/review.json`). Its verdicts are shown
as suggestions until accepted.

## AI when running

The scan (`classifier/aiuse.py`) also notes whether the program connects to an AI
system when it runs (AI libraries, `claude-docker` / the `claude` CLI, AI service
addresses and API keys, MCP code) and suggests: no AI connection · works without AI
but has a part that connects to it · needs AI · made for AI assistants (MCP server).
Comments, docstrings, tests and installers are ignored. The licensor confirms it and
says what the AI part does (Classification tab; **How AI detection works…**). It shows
in the AI column, the catalogue, and the LICENSE's AI DISCLOSURE.

## Licence

The licence must be open-source **and** say the software was made using Claude.
**Write LICENSE** writes MIT, BSD-3-Clause, Apache-2.0, GPL-3.0 (or-later / only),
LGPL-3.0-or-later or MPL-2.0 with an AI DISCLOSURE section in front, plus
THIRD-PARTY.md. Software importing GPL libraries (PyQt6) is recommended
GPL-3.0-or-later.

## Platforms

A track (Not planned … Supported) for Linux, Windows, macOS, iOS/iPadOS, Android and
OpenBSD, with evidence (installers, platform checks in the code, `windows-support`-style
branches, self-contained web pages) and blockers (Linux-only calls, Unix-only modules,
desktop libraries on phones, keyboard-only controls) from the scan.

## GitHub

`Check GitHub…` / `classifier github [--fix]` reads every repository and branch of the
account through `gh` (read-only), finds each software (folder remote, a same-named
folder or repository with matching files, or a link set by hand), and:

- private software in a public repository → made private (immediately when Settings
  says so);
- In Development and Private software in a repository → the repository deleted (its
  own) or its folder removed on every branch (shared), after a full backup clone in
  `~/.local/share/classifier/backups/`; you type the repository name to confirm;
- warnings for public releasable software without a passing licence, Excluded files
  found in public repositories, and unclassified public software;
- downloads: public releasable software with no release build, no release yet, or a
  release older than the files that go into it (see Downloads).

Deleting a repository needs `gh auth refresh -h github.com -s delete_repo` once.

## Commit and push

`Commit and push to GitHub…` (GitHub tab) / `classifier publish NAME [--dry-run]`
(`classifier/publish.py`): Releasable software to a public or private repository,
Private software (Finished but Private, Modular Suite but Private) only to a private
one, In Development and Private never. Files marked Excluded in Provenance stay out (a
file's own resolution beats its group's) and are removed if already pushed; caches,
review folders, secret-looking and >100 MB files are always left out; exclusions go in
the published `.gitignore`. LICENSE, THIRD-PARTY.md and PLATFORMS.md (Supported
platforms only) are added; supported-platform branches can be merged. Done in a
temporary clone: the software's folder is not changed.

## Downloads

`classifier/releases.py`. The catalogue's *Download the program* links come from each
repository's latest GitHub release. **Set up downloads…** (GitHub tab) / `classifier
release NAME --setup` writes a release build into a Python program's folder: a GitHub
Actions workflow (PyInstaller; Windows installer via Inno Setup, macOS disk image,
Linux AppImage, for the platforms marked Supported; a start-up check), the installer
script, release notes and a README Download section. It works out the start script,
packages (with known PyInstaller quirks), the data the program opens by name, icons and
macOS microphone/camera permission notes, and warns about what breaks once packaged:
saving beside itself without a `sys.frozen` check, QtWebEngine's sandbox in an
AppImage. **Build a release…** / `classifier release NAME --build` / `classifier
publish NAME --release` runs the workflow, waits, then updates the catalogue. Any
workflow that creates a GitHub release counts as a release build.

## Catalogue

`Catalogue…` / `classifier catalogue` writes one Markdown page listing every
Releasable software (never Private ones) with description, licence, source link,
supported platforms and per-platform install steps derived from its files.
**Publish to GitHub…** puts it in a repository's README.md (default: the profile
repository `owner/owner`), asking before creating or changing it.
After that it is kept up to date automatically (after Commit and push and Check
GitHub…, only when the page would change; Settings can turn this off; `classifier
catalogue --publish` does it by hand).

## claude-classifier-docker

`claude-classifier-docker/make.py` generates it from ZIS's `claude-docker`: same
lock-down, same Docker images and the same Claude sign-in (its credentials file is a
link to claude-docker's; `--own-login` keeps a separate one), its own config, policy
and session data. Windows are sized to fit the screen. Re-run `make.py` after ZIS's
claude-docker changes. make.py also fixes a ZIS quirk on GNOME/Wayland: the window
could start two terminals (one half-size on top). **Sign in to Claude…** (Provenance
tab, `classifier/signin.py`) signs in without the terminal: it runs Claude on `/login`
in a pseudo-terminal, shows the link with an Open button, takes the pasted code, and
ends the session so the sign-in is saved.

## Files

- Registry: `~/.config/classifier/registry.json` (`CLASSIFIER_CONFIG` overrides the folder)
- `classifier/`: `model.py` (groups, clearance), `scanner.py`, `licences.py`,
  `platforms.py`, `github.py`, `releases.py`, `review.py`, `gui.py`, `cli.py`, `helptext.py`
- Tests: `python3 -m unittest test_classifier` (no network)
- Icon: `python3 make_icon.py && ./install-desktop.sh`
